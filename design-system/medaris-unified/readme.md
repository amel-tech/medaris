# Medaris design system

Medaris is an online medrese: müderris and talebe, dersler, haftalar and live celseler, ezber
kartları. This is its design system: the tokens, the classes, the components, the rules and the
words.

It is new. It was designed from scratch in MDRS-131 and keeps nothing visual from the two earlier
systems. It keeps their file layout, the component contracts, the content files and the rules
that are not about the look.

## The idea: ink on paper

A medrese is built around a book: the matn, its şerh, the notes in the margin. Medaris should feel
like that book, not like a dashboard.

- The page is **paper** (kâğıt). The text is **ink** (mürekkep).
- The one primary action is written in ink. It is an ink button by day and a paper button by night.
- **Lâciverd** (lapis) is the only accent. It shows where you are: links, the current lesson, the
  active page, progress and the focus ring.
- **Lal** (red ink) marks what went wrong, what is destructive and what is live now. It is never
  decoration.
- Ornament comes only from the book: a hairline frame (cetvel), the calligrapher's dot (nokta) and
  blind-stamped cloth covers. There is no gold, no gradient and no arabesque.

## Decided and proposed

**Decided by the owner**

- A new system, from scratch, not bound by the earlier two.
- Scheherazade New for the Qur'an.
- Noto Naskh Arabic for classical text and for the whole Arabic interface.

The words, the states and the domain, moderation and voice rules come from the PRD, the owner's
decisions of 2026-09-26 and the launch brief (`content/vocabulary.json` lists the sources).

**Proposed in MDRS-131**

Everything else about the look is one proposal for the owner to accept: the palette, the other
three faces (Instrument Sans, Literata, Atkinson Hyperlegible Mono), the sizes, the shapes, the
night theme, the mark and the covers. It was chosen from several directions and then verified.

It passes WCAG 2.2 AA in both themes by construction, so no accessibility decision is open.
`contrast.md` lists every colour pair the system promises, by day and by night.
`tools/design-system/check.mjs` renders every card and measures what it paints.

The claude.ai/design project gets this directory when the owner pulls it with design sync. Until
then it is a proposal.

**Still the owner's, and not about the look**

Four decisions, in the table at the end of `rules.md`: who holds the system (SPEC-D3-08), icâzet at
launch (SPEC-D3-09), when the landing page moves onto this system (SPEC-D3-22), and when the apps
set `<html lang>` from the locale (SPEC-D3-23). The container words (SPEC-D3-11) were decided on
2026-09-30: ders, hafta, celse (MDS-WORD-01).

**Not verified**

Rendering on Windows and macOS, a real screen reader, and real Windows high-contrast mode. The
checks ran in Chromium on Linux, and forced colours were only emulated there.

The tools that check and generate these files are in the Medaris repo, in `tools/design-system/`.
Its README gives the full check.

## Using it

### For a prototype

1. Write static HTML and link `styles.css`.
2. Put `lang`, `dir` and `data-app` on `<html>`: `<html lang="tr" dir="ltr" data-app="tedris">`
   (MDS-LAY-03).
3. Use the `.mds-*` classes. Each component's `.prompt.md` gives its HTML.
4. Serve the page over http. Chromium does not load the icon sprite from `file://`.
5. Write real Turkish copy with the words in `content/` (MDS-VOICE-06, MDS-WORD-01).
6. Look at it by day and by night (below).

### For production code

Import the components in `components/`. Each `.jsx` is a thin wrapper over the same classes, so a
prototype and the code cannot drift. Read the component's `.prompt.md` first. It holds the
anatomy, the states and the rules the markup does not show.

A component writes a few words itself, such as "Kapat" or "Sıradaki". Each one is a prop with a
Turkish default (`content/ui-strings.json`). Nizam passes the *siz* forms (MDS-VOICE-01).

Nothing in the Medaris apps or libraries reads this directory yet.

## Fonts and what they cost

Five faces, one job each. Google Fonts serves each face in parts, so a page downloads only the
parts it paints.

| face | job | download (woff2) |
| -- | -- | -- |
| Instrument Sans | controls, tables, nav, labels, meta | about 41 KB, on every page |
| Literata | reading text and every title | about 70 KB, on every page; italic adds about 38 KB where it is used |
| Noto Naskh Arabic | classical text and the Arabic interface | about 111 KB, only where Arabic is shown |
| Scheherazade New | the Qur'an | about 67 KB, only where Qur'anic text is shown |
| Atkinson Hyperlegible Mono | meeting links and IDs | about 10 KB, only where one is shown |

So a Latin-only page with a meeting link downloads about 121 KB of fonts. A course page with
Qur'an, matn and şerh downloads about 328 KB. These were measured in headless Chromium on
2026-09-28.

- In production, load the faces with a `<link>` and `preconnect` in the page head, not with the
  `@import` in `tokens/fonts.css`. That saves one request in the chain.
- The Qur'an face is requested with Google's `text=` parameter, which serves it as one file. That
  keeps the waqf signs (ۖ ۗ ۚ) in Scheherazade New. The file is a dynamic Google Fonts kit, not a
  versioned file. If Google ever changes it, self-host the same file.

## Day and night

Both themes are complete, and every colour pair passes in both (`contrast.md`).

- A page follows the system preference.
- `data-theme="dark"` or `data-theme="light"` on `<html>` forces one theme.
- In Claude Design the theme switcher lists both themes (Theme Light, Theme Dark), because each is an
  `html[data-theme="…"]` rule. A viewer on a dark system picks Theme Light to see the day theme.
- `data-theme="dark"` on an element below `<html>` makes a night island. A light island inside a
  night page is not supported.
- The night theme swaps ink and paper: warm paper text on a blue-black page. The primary button
  becomes a paper button.
- Covers and platform dots look the same in both themes.

Look at every screen, card and prototype in both (MDS-COL-09). For a quick look, add
`data-theme="dark"` to `<html>`.

## Arabic and the Qur'an

- Put `lang="ar" dir="rtl"` on the Arabic element itself, never on a shared ancestor.
- An Arabic word inside Turkish text is `.mds-arabic`. It may carry harakat only in reading text.
  A run longer than three words is a block.
- A classical text (matn) is `.mds-arabic-text`: Noto Naskh Arabic at 26px.
- The Qur'an is `.mds-quran`: Scheherazade New, and nothing else. Bind each ayah's end mark to the
  word before it with a no-break space (U+00A0). The harakat switch never touches the Qur'an.
- A page or region in Arabic (`lang="ar"`) switches the whole interface to Noto Naskh Arabic,
  larger and one weight heavier. You add nothing per class.
- Ottoman in Arabic script is `lang="ota-Arab"`. Ottoman words in Latin letters (müderris,
  icâzet) are Turkish: `lang="tr"`.
- A classical text shows its source: author, death date and work (`.mds-source`).

The full rules are MDS-TYPE-04, MDS-TYPE-07 and MDS-TYPE-08.

## One system, five surfaces

Tedris (talebe), Nizam (müderris and managers), Nazır (moderation), Giriş (sign-in) and the landing
page share this one system. Only three things differ:

- **density:** Nizam puts `data-density="compact"` on its main region (MDS-LAY-02);
- **register:** *sen* in Tedris, *siz* in Nizam (MDS-VOICE-01);
- **chrome:** Tedris has a paper top bar; Nizam and Nazır have a paper sidebar.

No app gets a colour of its own (MDS-COL-01).

## The domain, briefly

Medrese (optional) → köşk → ders → hafta → celse. A ders is the course; a hafta holds the week's
celseler, one or several; a celse is one dated live meeting and has its own meeting link. Only
live lessons are authored for now.
Managers hide; they do not delete.

The words and states are data: `content/vocabulary.json`, `content/status-map.json`, and beside
them the meeting platforms, the recording providers and the time zones. Rules: MDS-WORD-01,
MDS-STAT-01, and the MDS-DOM and MDS-VOICE sections of `rules.md`.

## Known limits

- Instrument Sans draws I and l almost alike. That is why every identifier is set in mono.
- Literata has no ḳ. That letter falls back to another face.
- A light island inside a night page is not supported.

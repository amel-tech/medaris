# MDRS-151: the landing page on the unified design system

The landing app (`apps/landing`, `landing-web`) is the first app built on the
unified design system of MDRS-131 (`design-system/medaris-unified/`). Its six
pages are ports of the *Landing* screens of the canvas "Medaris Ekranları":
Karşılama (A1), Aydınlatma Metni (A2), Sık sorulan sorular, İletişim,
Kullanım şartları and Çerezler.

The shared foundation follows the canvas note *Tailwind ve paylaşılan kit*,
which the design team wrote for all three apps. Landing uses it first. tedris,
nizam, nazir and keycloak-theme still load `@medaris/ui/globals.css` and are
unchanged.

## What lives where

| Path | What | How it changes |
| -- | -- | -- |
| `libs/tokens/medaris.css` | the system's `tokens/*.css`, concatenated in `styles.css` order, without `fonts.css` | generated by `tools/design-system/sync-libs.mjs` |
| `libs/tokens/medaris-fonts.js` | the two Google Fonts URLs from `tokens/fonts.css` | generated |
| `libs/tokens/tailwind.css` | the `@theme inline reference` mapping from the canvas note | by hand |
| `libs/ui/src/styles/mds/*.css` | `components.css` and `medrese.css`, byte for byte | generated |
| `libs/ui/src/mds/glyphs.ts` | the generated block of `components/Icon.jsx` | generated |
| `libs/ui/src/mds/icon.tsx`, `logo.tsx` | ports of `Icon.jsx` and `Logo.jsx` | by hand |
| `libs/ui/src/styles/medaris.css` | the CSS entry, `@medaris/ui/medaris.css` | by hand |

`node tools/design-system/sync-libs.mjs --check` fails when a generated copy is
stale. The script is the only path from `design-system/` to the code, because
`.dockerignore` keeps `design-system/` out of every image. No new workspace
package was added, so the six Dockerfiles are unchanged.

## Three decisions that differ from the note

**Tailwind's preflight is off.** The note imports all of `tailwindcss`.
Measured on the landing pages, preflight undoes browser defaults that the
system's `tokens/base.css` relies on:

- `a { text-decoration: inherit }` took the underline off every link in running
  text;
- `ol, ul { list-style: none }` took the markers off every list in
  `.mds-reading`.

The canvas renders without preflight. `medaris.css` imports only
`tailwindcss/theme.css` and `tailwindcss/utilities.css`. Border utilities do
not need preflight in v4.

With preflight off, measured against the canvas screens in Chromium:

| Page | Width and theme | Result |
| -- | -- | -- |
| SSS, Çerezler | 1440 day, 390 day | pixel-identical |
| Aydınlatma Metni, Kullanım şartları | 1440 day | same height; only sub-pixel text runs differ, where a placeholder is a separate text node |
| Aydınlatma Metni | 390 night | same height; the same sub-pixel runs |
| Karşılama | 1440 day, 390 day, 1440 night | identical by eye, except "Medaris'i kim yürütüyor", which is not rendered (below) |

İletişim was checked by eye and by its states, not by pixels: without its
runtime, the canvas file draws the form, the error and the success card at
once.

**`fonts.css` is not in `medaris.css`.** Once Tailwind inlines the file, its
`@import url()` lines would land after other rules, where a browser ignores
them. The system's readme asks for a `<link>` with `preconnect` in production.
`apps/landing/app/[locale]/layout.tsx` does that with `medaris-fonts.js`.

**`libs/tokens/tailwind.css` is outside Biome.** Biome's Tailwind parser
accepts one `@theme` option, not two. `inline reference` needs both:

- `reference` keeps the colliding names (`--radius-control`, `--font-ui`…) from
  being redefined as themselves;
- `inline` makes utilities follow the night theme.

The file is listed in `biome.json`'s ignores next to the generated files.

## Landing app

- **Locale.** Turkish only: one locale, `localePrefix: "never"`, so the pages
  live at `/`, `/sss`… The root carries `<html lang="tr" dir="ltr"
  data-app="landing">` (MDS-LAY-03). `/en` and `/ar` are gone; Arabic and
  English are the system's next phase.
- **Leaving the landing app.** "Giriş yap", "Kayıt ol" and the köşk and ders
  links go through `/giris`, `/kayit` and `/tedris/…`. These are route
  handlers that redirect to `TEDRIS_URL` (`LANDING__TEDRIS_URL` in the root
  `.env`) at request time, so the static pages do not bake in an origin. A
  missing `TEDRIS_URL` answers 500 and logs it. **Production needs the value
  set.**
- **"Kayıt ol".** It goes to tedris's sign-in entry until tedris has one that
  asks Keycloak for registration (`prompt=create`, MDRS-101). The Keycloak
  sign-in page links to registration.
- **Content.** Köşkler and dersler are the canvas's sample content, in
  `content/karsilama.ts`, until MDRS-122 opens the lists to signed-out
  visitors.
  - Every placeholder of the legal pages is in `content/legal.ts`.
  - "Medaris'i kim yürütüyor" is not rendered while its text is still a
    placeholder.
- **İletişim.** The form draws every state of the canvas. It posts to
  `/api/iletisim`, which answers 503 until a destination for the messages is
  decided, so the visitor sees the error state.

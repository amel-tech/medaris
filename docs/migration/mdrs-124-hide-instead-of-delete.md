# MDRS-124 — hide instead of delete; only SYSTEM_ADMIN deletes for real

Owner's decision of 26 September: the people who run things never delete,
they hide; real deletion belongs to SYSTEM_ADMIN alone. This change covers the
issue's acceptance criteria — the permission change and the course level.
The other levels are listed under follow-up.

## What was done

**Matrix (`libs/common/src/authz`).**

- New scope `ARCHIVE` ("archive"), granted only on the course `KOSK_MANAGER`
  row.
- `DELETE` removed from course `KOSK_MANAGER`, course `MUDERRIS` and köşk
  `KOSK_MANAGER` (the madrasah nazır row lost it in MDRS-106). No role row on
  any entity grants `DELETE` now; a unit test pins that across the whole
  matrix, so a new row cannot bring it back unnoticed.

**Schema (migration `0018_hide_instead_of_delete`, generated by drizzle-kit).**

- `courses.archived_at` (timestamptz, null) and `courses.archived_by` (uuid,
  null, not a foreign key — like every other user column).
- The six foreign keys under a köşk move from `ON DELETE CASCADE` to
  `ON DELETE RESTRICT`: `courses.kosk_id`, `course_weeks.course_id`,
  `lessons.week_id`, `course_muderris.course_id`, `course_resources.course_id`,
  `enrollments.course_id`. `kosk_followers` and `madrasah_nazirs` stay
  CASCADE (membership rows, not content, and not named by the issue).
- New table `audit_log` (`actor_id`, `action`, `entity`, `entity_id`,
  `details` jsonb, `created_at`), no foreign keys so a row outlives what it
  describes.

The reversal is `apps/tedrisat/src/database/rollbacks/0018_hide_instead_of_delete.down.sql`
(apply by hand, then delete 0018's row from `drizzle.__drizzle_migrations`).
Rolling back makes any hidden course visible again and drops the audit log.

**Endpoints.**

| Route | Scope | Who passes |
| -- | -- | -- |
| `POST /courses/:id/archive` (Gizle) | `ARCHIVE` | köşk manager, SYSTEM_ADMIN |
| `POST /courses/:id/restore` (Geri al) | `ARCHIVE` | köşk manager, SYSTEM_ADMIN |
| `GET /kosks/:koskId/courses?archived=true` (Arşiv) | owner check in the service | köşk manager, SYSTEM_ADMIN; others 403 |
| `DELETE /courses/:id` | `DELETE` | SYSTEM_ADMIN only |
| `DELETE /kosks/:id` | `DELETE` | SYSTEM_ADMIN only |

A missing or malformed course id answers 404 before the matrix
(`byExistingCourse`, mirroring `byExistingKosk`). Hiding a hidden course, or
restoring a live one, changes nothing — neither the stamp nor the version.
Both real writes bump the course `version`, so an editor holding the old one
gets 409 instead of saving over the hide.

**Reads.** A hidden course is left out of `GET /kosks/:koskId/courses`,
`GET /courses/enrolled`, `GET /me` (`teaches`), the pending-enrollment list,
and the course / student / müderris counts on köşk responses. `GET
/courses/:id` (and therefore `enroll`) answers 404 for it to everyone the
`ARCHIVE` scope does not cover — the same way drafts behave. Nothing is
deleted; enrollments survive and come back on restore. Course responses carry
`archivedAt` / `archivedBy`.

**Real delete.** `course/course-purge.ts` deletes lessons, weeks, müderris,
resources, enrollments and the course explicitly, in one transaction, after a
`FOR UPDATE` on the course (köşk) row, and writes one `audit_log` row with the
name and a count per table. The köşk delete runs the same purge over all its
courses, hidden ones included, then the followers and the köşk.

**Tests.** New `test/e2e/hide-instead-of-delete.e2e.spec.ts` (9 tests, real
AuthGuard with minted tokens) and `test/e2e/hide-instead-of-delete-migration.e2e.spec.ts`
(1 test). The two old "owner deletes" e2e cases in `course` and `kosk` now
expect 403. Four suites cleaned with `DELETE FROM kosks`, which RESTRICT now
refuses; they use `COURSE_TREE_TABLES` (children first) from
`test/helpers/test-database.helper.ts`. The OpenAPI spec and the generated
client were regenerated.

## Acceptance criteria → evidence

| Criterion | Test |
| -- | -- |
| köşk manager 403 on `DELETE /kosks/:id` and `DELETE /courses/:id` | `hide-instead-of-delete.e2e` › DELETE is SYSTEM_ADMIN's alone |
| manager hides and restores; hidden course 404 for talebe, in no list | › lets the köşk manager hide their course… |
| raw SQL `DELETE` of a course fails because of RESTRICT | › refuses a raw SQL DELETE… (23503, constraint `confdeltype = 'r'`) |
| admin delete removes the course and children and records an audit entry | › SYSTEM_ADMIN's delete (course and köşk) |
| migration reversible, changes no existing row | `hide-instead-of-delete-migration.e2e` |

## What was verified

- `nx affected -t typecheck test build lint module-boundaries` against
  `687bab9`: green on all six affected projects (common, tedrisat, teskilat,
  services, nizam-web, tedris-web). tedrisat: 31 test files, 474
  tests. common: 6 files, 61 tests. teskilat: 5 files, 25 tests.
- `node tools/ci/assert-openapi-spec-fresh.mjs`: the spec is fresh.
- Postgres reports a RESTRICT refusal as SQLSTATE 23503 (foreign_key_violation),
  not 23001. The test checks the refusing constraint's `confdeltype` instead.

## What was not verified

- Not run against a production-sized database. The migration drops and
  re-creates six foreign keys, and re-creating them validates every existing
  row. How long that takes on real data was not measured.
- nizam-web was not exercised in a browser. It never called `deleteCourse` or
  `deleteKosk`, so nothing there broke. It does not use the new endpoints yet
  either.

## Follow-up

- Issue item 1 for the other levels: `archived_at`/`archived_by` and hide/
  restore on `madrasahs` (nazır), `kosks` (köşk manager), plus `archived_by`
  on `course_weeks` and `lessons` (müderris), and `lesson_recordings` with
  MDRS-119.
- Issue item 6, nizam: "Gizle", an "Arşiv" filter with "Geri al", and the
  admin-only "Kalıcı olarak sil" behind a confirmation that names what will be
  lost. The API side (`archived=true`, archive/restore, admin delete) is
  ready for it.
- A müderris keeps `EDIT` on a hidden course's lessons (`/lessons/*`), and an
  enrolled talebe can still `PUT /courses/:id/progress` on it. Neither exposes
  the course, but a later pass may want writes on a hidden course refused.
- No read endpoint for `audit_log` yet.

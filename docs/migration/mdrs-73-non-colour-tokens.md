## 2. Names that are not the Figma names, and why

The files sit inside `@theme` next to Tailwind v4's defaults. Several Figma
names already mean something there. Each was measured on tailwindcss 4.3.3
before the name was chosen:

| Figma name as a Tailwind key | What it would have done | Name used |
| -- | -- | -- |
| `--spacing-md: 16px` | `max-w-md`, `w-md`, `size-md` resolve `--spacing-*` before `--container-*`: `max-w-md` became 16px | `--space-*` |
| `--breakpoint-mobile/-desktop` | extra `container` max-width steps (24.375rem, 90rem) in every app — found in the built CSS of nazir | `--bp-*` (values only) |
| `--radius-xs/-xl/-full` | restyle `rounded-xs`, `rounded-xl`, and replace `rounded-full`'s `calc(infinity * 1px)` | `--corner-radius-*` |
| `--border-width-s/-l` | `border-s` / `border-l` emit a second, all-sides rule | `--border-weight-*` |
| `--leading-tight/-snug`, `--tracking-tight/-normal` | other values than Tailwind's | `--line-height-*`, `--letter-spacing-*` |

Kept in Tailwind namespaces because they collide with nothing, or collide
with exactly the same value: `--font-cairo`, `--font-ibm-plex-sans`,
`--font-weight-*` (seven of eight equal Tailwind's; `regular` is new),
`--text-<display…footnote>`, and the seven shadows.

**Shadows.** The Figma effect styles are Tailwind's default shadows: same
layers and offsets, alpha equal at 8 bits. The file lists each pair of
layers in the opposite order and spells 2xs as `0 1px 0 0`. The first
version copied that spelling; the built CSS of all four Next apps then
differed in every `--tw-shadow` rule (same pixels, different bytes). The
shipped version writes Tailwind's notation, and
`test/figma-fidelity.spec.ts` checks each against the Figma value layer by
layer (`normaliseShadow`).

**Proposals.** `--line-height-snug` (1.25), `--line-height-body` (1.5) and
`--letter-spacing-tight` (-0.02em) are not in the `.fig` — every text style
there is 100% / 0. They are the design system's own proposals, carried with
its `proposed` label as `PROPOSAL`; a test fails if the label and the
mirror's disagree. Not carried: `--ring-focus-brand` (the proposed fix for
the focus ring is an open decision), the mirror's Arabic and mono families
(not in the Figma collection).

## 3. Radius decision (AC3)

`libs/ui/styles/theme.css` now maps `--radius-sm/md/lg/xl` to
`--corner-radius-xs/s/m/l`: 6, 8, 12, 20px (was 6, 8, 10, 16). The two
off-scale values move to the step the design system assigns what shadcn
draws with them: `rounded-lg` is cards, dialogs and alerts → `m` (12);
`rounded-xl` is the sidebar inset, a large surface → `l` (20). Both are
equidistant from their neighbours on the scale, so usage decided, and the
order sm < md < lg < xl is kept.

**This changes nothing an app renders.** No file imports
`libs/ui/styles/theme.css` (`libs/ui/package.json` exports only
`./globals.css`; grep finds no other reference). The radii the five web
apps render come from `libs/ui/src/styles/globals.css`, derived from
`--radius: 0.625rem` (lg 10px, xl 14px). Moving those onto the tokens is a
visible change in every app and is outside this AC — see §6.

## 6. Follow-ups (not done here)

- **Live radii.** `libs/ui/src/styles/globals.css:115-118` still derives
  `--radius-sm/md/lg/xl` from `--radius: 0.625rem` (6 / 8 / 10 / 14px). Pointing
  them at `--corner-radius-*` changes every app's `rounded-lg` and
  `rounded-xl`; it needs its own issue and a visual review.
- **Fonts are named, not loaded.** The tokens name Cairo and IBM Plex Sans;
  `libs/ui/src/styles/globals.css` loads Cairo and Inter, and nothing loads
  IBM Plex Sans. Known divergence (see the `medaris-design-system` skill).
- **Breakpoints as a layout grid.** `--bp-*` are values only. Registering
  them as Tailwind breakpoints changes `container` in every app (§2).
- **A mirror-only change does not make `tokens` affected.** `.nxignore`
  excludes `design-system/`, so a file input on it hashes nothing (measured:
  a changed `design-system/tokens/spacing.css` still replayed the cached
  green). The `test` target therefore takes a runtime input,
  `cat design-system/tokens/*.css` — measured: the same change now misses
  the cache and turns `figma-fidelity.spec.ts:80` red. That fixes the
  cache, not `nx affected`, which reads the project graph: a PR touching
  only `design-system/` still does not select `tokens:test`. Closing that
  needs the mirror to become an Nx input, which `.nxignore` exists to
  prevent (MDRS-92/93); not changed here.
- The contrast audit and the focus ring are untouched, as the issue says.

# Çalışma soruları, Faz 1: the API (MDRS-248)

Date: 27 November 2026. Scope: `apps/tedrisat` and the generated client in
`libs/services`. No screen changes here: nazar's preparation (Faz 2) and
tedris' solving screens (Faz 3) build on the routes below.

## What the feature is

A hoca prepares a group of questions like an exam, a *çalışma seti*, and
publishes it. A talebe of the course opens it whenever they like: there is no
clock; when they finish they see their result and the correct options at once,
and they may solve it again as often as they like. Later (Faz 4, below) a
talebe may solve every question of a course's sets, or N of them at random.

## The model

- **No second question engine.** A set is a row of `online_exams` with the new
  enum column `kind` (`exam_kind`: `EXAM` | `PRACTICE`, default `EXAM`, not
  null). Its questions, options and topics are the exam's own
  (`exam_questions`, `exam_options`, `exam_question_topics`), prepared through
  the same `online-exams` routes under the same `exam.prepare`, with the same
  `version` (EXAM_STALE) and the same lock once published (EXAM_LOCKED). The
  check `online_exams_kind_lesson_check` keeps a set from ever having a celse.
- **Publishing a set** makes no celse, so nothing reaches a calendar or a
  notification. It asks for no length, no late window and no zeroth question,
  and copies none. Its one condition is a complete question (by the exam's own
  `lacksOf`); its incomplete questions are not refused but never solved, and
  the question counts the talebe see are of the complete ones. The times in
  the publish body are not read for a set.
- **Taking a set back to a draft** is allowed until a talebe has started it;
  after that it is EXAM_LOCKED, as an exam is once it has opened. Starting an
  attempt holds the set's row for share and the take-back holds it for update,
  so the two never cross. Because a set with attempts never goes back to a
  draft, its questions never change under an attempt.
- **No points editor.** Every question of a set weighs the same; the part of a
  question an answer gets is the exam's `earnedPart` (so IN_SHARES gives a
  part). A question is CORRECT when it gets the whole part, WRONG when it is
  answered and gets less, BLANK when nothing is chosen. The percentage is the
  parts summed exactly over the number of questions, in hundredths, rounded
  half up once (`practice/domain/practice.ts`).
- **Attempts are separate tables**; `exam_attempts` is not touched.
  `practice_attempts` (id, course_id, user_id, set_id, pool_mode,
  question_order, option_order, current_question_id, started_at, finished_at,
  correct/wrong/blank counts, score_hundredths), index `(user_id, course_id)`,
  index on `set_id`, and the partial unique index `practice_attempts_open_uq`
  on `(user_id, set_id) where finished_at is null and set_id is not null`: one
  attempt of a set in progress per talebe. `practice_answers` (attempt_id,
  question_id, option_ids, saved_at; primary key on the pair). Every foreign
  key is RESTRICT, as under every course. The order of the questions and of
  each question's options is drawn with `drawOrder` for each attempt; an
  answer is saved the moment it is chosen and checked with `answerFits`. There
  is no clock, no holder and no tab count.
- **The pool (Faz 4).** `set_id` null with `pool_mode` (`ALL` | `RANDOM`) is a
  solving of the course's question pool; the check
  `practice_attempts_pool_check` says `pool_mode` is set exactly when `set_id`
  is null. See *The pool* below.

Migration `0081_practice_sets` (generated by `drizzle-kit generate`, then
renumbered by hand as 0080 was, with its snapshot `meta/0081_snapshot.json`);
the hand rollback is `database/rollbacks/0081_practice_sets.down.sql`. The
course purge deletes the practice answers and attempts before the sets and
their questions (`deleteCourseOnlineExams`), and `COURSE_TREE_TABLES` lists the
two tables.

## Routes

The team, on the existing routes:

- `POST courses/:id/online-exams` takes an optional `kind` (EXAM when left
  out). `GET courses/:id/online-exams` takes `?kind=` and lists EXAM when it is
  left out, so the exam list never shows a set. Both answers, and the draft,
  carry `kind`; a set's status is DRAFT or OPEN.
- Refused on a set with 409 `EXAM_KIND_MISMATCH`: the points
  (`PUT …/questions/:questionId/points`), a length in `PATCH online-exams/:id`,
  the results, one talebe's answers and the early close. A set's routes on an
  exam answer 404 `PRACTICE_SET_NOT_FOUND`; the exam attempt routes go by a
  celse, which a set has none of.

The talebe (`apps/tedrisat/src/practice`):

| Route | operationId |
| -- | -- |
| `GET courses/:id/practice-sets` | `listPracticeSets` |
| `GET my-practice-sets` | `listMyPracticeSets` |
| `POST practice-sets/:setId/attempts` | `startPracticeAttempt` (returns the attempt in progress when there is one) |
| `GET practice-sets/:setId/attempts` | `listPracticeAttempts` |
| `GET practice-attempts/:attemptId` | `getPracticeAttempt` |
| `PUT practice-attempts/:attemptId/answers/:questionId` | `savePracticeAnswer` |
| `POST practice-attempts/:attemptId/finish` | `finishPracticeAttempt` |

Access is `course.view` on the course (by the course, the set or the caller's
own attempt; another person's attempt is 404 before any code is asked) and
`CourseService.mayWriteAsTalebe` in the service: an ENROLLED or COMPLETED seat,
no ban, the course's content open, the same check a talebe's note, question
and watch record use. Not a talebe of the course: 403 `PRACTICE_FORBIDDEN` on
the course's list, 404 on a set or an attempt. While an attempt is in
progress no answer carries `correct` (nor the counts); once finished, each
option carries it, each question its `outcome` and `part`, and `result` the
counts and `percent`. The lists give each set's question count, the caller's
finished attempts, their latest percentage and the id of the attempt in
progress.

Generated client: `PracticeApi` (`createTedrisatAPIs().practice`), the models
`PracticeSetSummaryResponse`, `PracticeAttemptResponse`,
`PracticeQuestionResponse`, `PracticeOptionResponse`, `PracticeResultResponse`,
`PracticeAttemptSummaryResponse`, `PracticeAnswerSavedResponse`,
`SavePracticeAnswerDto`, the enums `ExamKind`, `PracticeAttemptStatus`,
`PracticeOutcome`, and `kind` on `CreateOnlineExamDto`,
`OnlineExamSummaryResponse`, `OnlineExamDraftResponse` and
`ListOnlineExamsRequest`.

## The pool (Faz 4)

The pool of a course is the complete questions of its **published çalışma
setleri**: no exam's question (kind EXAM, published or not) and no draft
set's. A talebe solves all of it or N of it at random, as often as they like,
one pool attempt in progress per course at a time.

- **Routes** (`apps/tedrisat/src/practice`), under `course.view` on the course
  and `mayWriteAsTalebe` in the service (403 `PRACTICE_FORBIDDEN` otherwise):

  | Route | operationId |
  | -- | -- |
  | `GET courses/:id/practice-pool` | `getPracticePool`: the pool's question count, the open pool attempt's id, the caller's ten latest pool attempts (mode, question count, status, result) |
  | `POST courses/:id/practice-pool/attempts` `{mode, count?}` | `startPracticePoolAttempt`: returns the open pool attempt when there is one, whatever is asked |

  `mode: RANDOM` needs `count` from 1 to the pool's size; out of range (or
  ALL on an empty pool) is 400 `PRACTICE_POOL_COUNT_INVALID`, a missing or
  non-integer `count` or another mode 400 `VALIDATION_ERROR`. RANDOM is the
  first N of a fresh `drawOrder` of the pool, so no question twice
  (`drawPool`, `poolCountFits` in `practice/domain/practice.ts`).
- **The attempt routes are the same.** `GET/PUT/POST practice-attempts/...`
  read a pool attempt as a set's; the attempt's questions are now read by id
  (`PracticeRepository.questionsByIds`: only the columns solving and scoring
  read, the question's set title, its options), for a set's attempt too.
  `PracticeAttemptResponse.setId` is nullable (null for a pool attempt), it
  carries `poolMode`, its `title` is empty for a pool attempt, and every
  question carries `setTitle`, the title of the set it came from.
- **One open pool attempt per talebe and course**: the partial unique index
  `practice_attempts_pool_open_uq` on `(user_id, course_id) where finished_at
  is null and set_id is null`, migration `0082_practice_pool` (generated, then
  renumbered by hand as 0080 and 0081 were, snapshot `meta/0082_snapshot.json`),
  rollback `database/rollbacks/0082_practice_pool.down.sql`.
- **The lock.** Starting a pool attempt holds the course's published sets for
  share while it draws; taking a set back to a draft is refused (EXAM_LOCKED)
  once a pool attempt of its course drew one of its questions, as once a
  talebe started the set itself. So no question changes under a pool attempt.
- **Hoca's view.** `GET courses/:id/practice-set-stats`
  (`listPracticeSetStats`, `exam.prepare`): per published set with a finished
  attempt, how many talebe finished it, how many times, and the average
  percentage (`round(avg(score_hundredths))`). Pool attempts are not a set's
  and are not counted.
- **tedris**: `/calisma-sorulari` shows, under each course heading with a
  non-empty pool, "Tüm soruları çöz ({count})", "Rastgele soru çöz" with a
  number field (default `min(50, count)`, a plain GET form), or "Karışık
  denemeye devam et" while a pool attempt is open. `/calisma-sorulari/havuz/
  [courseId]?mod=ALL|RANDOM&sayi=N` starts it in the browser, as a set's page
  does; the result names each question's set ("Set: …"), and its "Tekrar
  çöz" leads back to the course's pool buttons.
- **nazar**: the set list shows, beside each published set, "{n} talebe {k}
  kez çözdü · ortalama %x" or "Henüz çözülmedi"; a side read, so the list
  stays when it fails.

### Verified

- `apps/tedrisat/test/unit/practice/practice.spec.ts`: ALL draws every
  question; RANDOM draws exactly N with none twice; `poolCountFits` refuses
  0, a fraction, a missing count, more than the pool and an empty pool.
- `apps/tedrisat/test/e2e/practice-pool.e2e.spec.ts`: the pool counts only
  the published sets' complete questions (no draft's, no published exam's);
  ALL draws them all, each with its set's title and no `correct` before the
  finish; RANDOM draws N distinct ones and a second start returns the open
  attempt; out-of-range and invalid bodies are 400 and leave no row; an empty
  pool is refused; answer, read and finish work on a pool attempt and the
  result names the set; a pending, a stranger and the müderris are 403; a set
  is locked once a pool attempt drew from it; the stats count a set's
  finishes, not the pool's, and refuse a talebe.
- tedris `test/practice.spec.ts`, `test/practice-take.spec.ts` and nazar
  `test/exam-practice-page.spec.tsx` for the screens.
